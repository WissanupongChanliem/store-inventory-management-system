คู่มือสำหรับ Backend TypeScript

ทำ CRUD ด้วย Drizzle ORM

คู่มือนี้พาใช้ Drizzle ORM กับ TypeScript และ SQLite ตั้งแต่ประกาศ schema จนถึงเพิ่ม อ่าน แก้ไข และลบสินค้า โดยใช้ตัวอย่างจากระบบจัดการร้านค้า

Createdb.insert()
Readdb.select()
Updatedb.update()
Deletedb.delete()

ตัวอย่างสมมติว่ามีตาราง products ที่เก็บชื่อสินค้า จำนวนคงเหลือ และราคาเป็นสตางค์

Schema ทำให้ TypeScript รู้จักตาราง

กำหนดตารางและชนิดข้อมูลครั้งเดียว จากนั้น import ตารางและ type ที่อนุมานได้ ไปใช้ใน service หรือ route 

import { integer, sqliteTable, text } from "drizzle-orm/sqlite-core";

export const products = sqliteTable("products", {
  id: integer("id").primaryKey({ autoIncrement: true }),
  name: text("name").notNull(),
  amount: integer("amount").notNull(),
  priceSatang: integer("price_satang").notNull(),
  createdAt: text("created_at").notNull(),
  updatedAt: text("updated_at").notNull(),
});

export type Product = typeof products.$inferSelect;
export type NewProduct = typeof products.$inferInsert;

Product คือข้อมูลที่อ่านจากฐานข้อมูล ส่วน NewProduct คือข้อมูลสำหรับ insert โดย TypeScript อนุมาน field ที่จำเป็นและชนิดข้อมูลจาก schema

Schema ใน Drizzle ให้ type และ query API แต่ไม่ได้สร้างตารางใน SQLite ให้อัตโนมัติ ต้องสร้างตารางด้วย migration หรือ SQL ก่อนเรียก CRUD

เชื่อมต่อฐานข้อมูล

import { createDatabase } from "./db";

const { db, close } = createDatabase("./data/store.sqlite");

// ปิด connection เมื่อแอปกำลัง shutdown
process.on("SIGTERM", () => {
  close();
});

ในโปรเจกต์นี้ createDatabase ตั้งค่า Drizzle พร้อม schema ให้แล้ว และ export ตารางกับ type จาก server/src/db

Create — เพิ่มข้อมูล

ใช้ insert().values() ส่งเฉพาะ field ที่ต้องบันทึก

import { products, type NewProduct } from "./db";

export function createProduct(input: {
  name: string;
  amount: number;
  priceSatang: number;
}) {
  const now = new Date().toISOString();
  const values: NewProduct = {
    name: input.name.trim(),
    amount: input.amount,
    priceSatang: input.priceSatang,
    createdAt: now,
    updatedAt: now,
  };

  const product = db
    .insert(products)
    .values(values)
    .returning()
    .get();

  if (!product) {
    throw new Error("PRODUCT_CREATE_FAILED");
  }
  return product;
}

returning().get() คืน row ที่เพิ่มแล้ว 1 รายการ และตัวอย่างตรวจกรณีไม่มี row ที่คืนมาก่อนส่งผลลัพธ์กลับ

ตรวจ input ก่อนบันทึก เช่น name ต้องไม่ว่าง และ amount/priceSatang ต้องเป็นจำนวนเต็มในช่วงที่ API กำหนด อย่ารับ id หรือราคาจาก client โดยไม่ตรวจ

Read — อ่านข้อมูล

อ่านสินค้าตาม ID

import { eq } from "drizzle-orm";
import { products } from "./db";

export function getProductById(id: number) {
  return db
    .select()
    .from(products)
    .where(eq(products.id, id))
    .get();
}

const product = getProductById(1);
if (!product) {
  // ให้ route ตอบ 404 PRODUCT_NOT_FOUND
}

อ่านรายการ เรียงลำดับ และแบ่งหน้า

import { asc } from "drizzle-orm";

const items = db
  .select()
  .from(products)
  .orderBy(asc(products.name), asc(products.id))
  .limit(50)
  .offset(0)
  .all();

`.all()` ใช้ทำอะไร

สำหรับ SQLite driver ที่ใช้ better-sqlite3, .all() จะรัน query แล้วคืนแถวผลลัพธ์ทั้งหมดเป็น array โดยยังเคารพ where, limit และ offset ถ้าไม่พบแถวจะได้ [] ไม่ใช่ undefined 

const items = db.select().from(products).all();
// items เป็น Product[]; ถ้าไม่มีสินค้า items จะเป็น []

const firstItem = db
  .select()
  .from(products)
  .where(eq(products.id, 1))
  .get();
// get() คืนแถวเดียว หรือ undefined ถ้าไม่พบ

ใช้ .all() เมื่อต้องการรายการ ใช้ .get() เมื่อต้องการแถวเดียว ส่วน .run() ใช้รันคำสั่งเปลี่ยนข้อมูล โดยไม่คืนแถว (เช่น update/delete ที่ไม่มี returning())

ค้นหาชื่อ

import { like } from "drizzle-orm";

const search = "milk";
const items = db
  .select()
  .from(products)
  .where(like(products.name, `%${search}%`))
  .orderBy(asc(products.name), asc(products.id))
  .all();

Drizzle bind ค่า query ให้ ไม่ต้องต่อ input ลงใน SQL string เอง หากต้องการให้ `%` และ `_` เป็นตัวอักษรค้นหาตามจริง ให้ escape wildcard ก่อนใช้ like

Update — แก้ไขข้อมูล

ระบุ field ที่ต้องการแก้ใน set() และเลือกแถวด้วย where() เสมอ 

import { eq } from "drizzle-orm";
import { products } from "./db";

export function updateProductName(id: number, name: string) {
  const [updated] = db
    .update(products)
    .set({
      name: name.trim(),
      updatedAt: new Date().toISOString(),
    })
    .where(eq(products.id, id))
    .returning()
    .all();

  return updated;
}

ถ้า updated เป็น undefined แปลว่าไม่พบ ID นั้น ให้ route แปลงเป็น response 404 PRODUCT_NOT_FOUND

แก้จำนวนคงเหลือและราคา

const [updated] = db
  .update(products)
  .set({
    amount: 10,
    priceSatang: 3000,
    updatedAt: new Date().toISOString(),
  })
  .where(eq(products.id, 1))
  .returning()
  .all();

Delete — ลบข้อมูล

import { eq } from "drizzle-orm";
import { products } from "./db";

export function deleteProduct(id: number) {
  const [deleted] = db
    .delete(products)
    .where(eq(products.id, id))
    .returning()
    .all();

  return deleted;
}

const deleted = deleteProduct(1);
if (!deleted) {
  // ให้ route ตอบ 404 PRODUCT_NOT_FOUND
} else {
  // ให้ route ตอบ 204 โดยไม่มี response body
}
การลบสินค้าในระบบนี้ต้องไม่ลบประวัติการขาย รายการขายเก็บชื่อสินค้าและราคา เป็น snapshot และไม่ผูก productId ย้อนกลับไปยังตารางสินค้า

Comparison operators — เงื่อนไขใน where()

import operator จาก drizzle-orm แล้วส่งเงื่อนไขเข้า .where() แทนการต่อข้อความ SQL ด้วยตัวเอง

Operatorความหมายตัวอย่าง
eq(column, value)เท่ากับ =รหัสเท่ากับ 5
ne(column, value)ไม่เท่ากับ <>จำนวนไม่เท่ากับ 0
gt(column, value)มากกว่า >ราคามากกว่า 5000
gte(column, value)มากกว่าหรือเท่ากับ >=จำนวนอย่างน้อย 1
lt(column, value)น้อยกว่า <ราคาน้อยกว่า 5000
lte(column, value)น้อยกว่าหรือเท่ากับ <=ราคาสูงสุด 5000
between(column, min, max)อยู่ในช่วง รวมค่าขอบทั้งสองด้านราคา 1000 ถึง 5000
notBetween(column, min, max)อยู่นอกช่วงราคาไม่อยู่ระหว่าง 1000 ถึง 5000
inArray(column, values)ค่าอยู่ในรายการ INID อยู่ในรายการที่เลือก
notInArray(column, values)ค่าไม่อยู่ในรายการ NOT INID ไม่อยู่ในรายการที่ยกเว้น
like(column, pattern)ตรงกับรูปแบบข้อความ LIKEชื่อมีคำว่า milk
notLike(column, pattern)ไม่ตรงกับรูปแบบข้อความชื่อไม่ตรงกับรูปแบบที่กำหนด
isNull(column)ค่าเป็น NULLคอลัมน์ที่ยังไม่มีค่า
isNotNull(column)ค่าไม่เป็น NULLคอลัมน์ที่มีค่าแล้ว

ใช้ and(), or() และ not() เพื่อรวม/กลับเงื่อนไข และใช้ isNull() แทนการเปรียบเทียบ NULL ด้วย eq() 

import { and, eq, gt, like, lte, or } from "drizzle-orm";

const items = db
  .select()
  .from(products)
  .where(
    and(
      gt(products.amount, 0),
      lte(products.priceSatang, 5000),
      or(
        like(products.name, "%milk%"),
        eq(products.id, 10),
      ),
    ),
  )
  .all();

ตัวอย่างช่วงราคาและรายการ ID:

import { between, inArray } from "drizzle-orm";

const priceRange = db
  .select()
  .from(products)
  .where(between(products.priceSatang, 1000, 5000))
  .all();

const selected = db
  .select()
  .from(products)
  .where(inArray(products.id, [2, 5, 10]))
  .all();

LIKE ใช้ wildcard % แทนข้อความกี่ตัวก็ได้ และ _ แทนหนึ่งตัวอักษร ส่วน between รวมค่าขอบเขตต้นและปลายด้วย

JOIN — อ่านข้อมูลจากหลายตาราง

ใช้ .innerJoin() เมื่ออยากได้เฉพาะแถวที่มีข้อมูลจับคู่กัน และ .leftJoin() เมื่อต้องการเก็บแถวจากตารางหลักไว้ แม้ไม่มีข้อมูลจับคู่ ใช้ eq() ระบุคอลัมน์ที่สัมพันธ์กัน

ตัวอย่าง: รายการขายพร้อมรายการสินค้า

import { eq } from "drizzle-orm";
import { saleItems, sales } from "./db";

const rows = db
  .select({
    saleId: sales.id,
    createdAt: sales.createdAt,
    itemName: saleItems.name,
    quantity: saleItems.quantity,
    lineTotalSatang: saleItems.lineTotalSatang,
  })
  .from(sales)
  .innerJoin(saleItems, eq(sales.id, saleItems.saleId))
  .where(eq(sales.id, 12))
  .all();

ผลลัพธ์เป็น array ของ object ที่เลือกไว้ แต่ละรายการขายจะปรากฏซ้ำตามจำนวน sale item ที่จับคู่ได้ ตัวอย่างนี้เลือกเฉพาะบางคอลัมน์ แทนการคืนทั้งแถวของสองตาราง

ใช้ LEFT JOIN เพื่อเก็บแถวจากตารางหลัก

const rows = db
  .select({
    saleId: sales.id,
    itemName: saleItems.name,
  })
  .from(sales)
  .leftJoin(saleItems, eq(sales.id, saleItems.saleId))
  .all();

// ถ้า sale ไม่มี saleItem, itemName จะเป็น null
ใน schema นี้ saleItems เก็บชื่อและราคาขายเป็น snapshot และ productId ไม่ได้เป็น foreign key ไปยัง products. สำหรับประวัติการขาย ให้ใช้ค่าจาก snapshot เพื่อไม่ให้การลบหรือแก้ไขสินค้า เปลี่ยนข้อมูลการขายย้อนหลัง

Drizzle ยังมี join รูปแบบอื่นตาม dialect และเวอร์ชันฐานข้อมูล เช่น rightJoin() และ fullJoin(); สำหรับ SQLite ตัวอย่างนี้ใช้ innerJoin() และ leftJoin() เพื่อให้เข้ากันได้กว้างกว่า

Relational queries — อ่านข้อมูลตาม relations ที่ประกาศไว้

เมื่อ Drizzle ถูกสร้างพร้อม schema และประกาศ relation แล้ว ใช้ db.query อ่านข้อมูลแบบ nested ได้ โปรเจกต์นี้ประกาศ relation ระหว่าง sales กับ saleItems ไว้ 

import { eq } from "drizzle-orm";
import { sales } from "./db";

const sale = db.query.sales.findFirst({
  where: eq(sales.id, 12),
  with: { items: true },
});

// sale มีข้อมูล sale และ items เป็น array;
// ถ้าไม่พบ sale จะได้ undefined

relational query เหมาะกับข้อมูลที่ต้องการ object ซ้อนกัน ส่วน explicit innerJoin()/leftJoin() เหมาะเมื่ออยากเลือกคอลัมน์ หรือจัดรูปผลลัพธ์เอง

Transaction — ทำหลายคำสั่งให้สำเร็จหรือล้มเหลวพร้อมกัน

สมมติว่ามีตาราง accounts(id, name) และ accountSettings(accountId, theme) ต้องสร้างบัญชีและค่าตั้งต้นให้สำเร็จพร้อมกัน 

import { accounts, accountSettings } from "./db";

const account = db.transaction((tx) => {
  const created = tx
    .insert(accounts)
    .values({ name: "Ada" })
    .returning()
    .get();

  if (!created) throw new Error("ACCOUNT_CREATE_FAILED");

  tx.insert(accountSettings)
    .values({ accountId: created.id, theme: "dark" })
    .run();

  return created;
});

ถ้าการ insert ค่าตั้งค่าล้มเหลว การสร้างบัญชีก็ rollback ไปด้วย

Atomic update — เพิ่มตัวนับในคำสั่งเดียว

สมมติว่ามีตาราง counters(id, value).

ไม่ควร: อ่านค่ามาคำนวณ แล้วเขียนกลับแยกอีกคำสั่ง

import { eq } from "drizzle-orm";
import { counters } from "./db";

const current = db
  .select({ value: counters.value })
  .from(counters)
  .where(eq(counters.id, 1))
  .get();

if (!current) throw new Error("COUNTER_NOT_FOUND");

db.update(counters)
  .set({ value: current.value + 1 })
  .where(eq(counters.id, 1))
  .run();

ถ้าสอง request อ่านค่าเดิมพร้อมกัน ทั้งคู่อาจเขียนค่าเดิมบวกหนึ่งกลับไป ทำให้การเพิ่มหนึ่งครั้งหายไป (lost update)

แนะนำ: ให้ฐานข้อมูลคำนวณใน UPDATE เดียว

import { eq, sql } from "drizzle-orm";
import { counters } from "./db";

const step = 1;
const updated = db
  .update(counters)
  .set({ value: sql`${counters.value} + ${step}` })
  .where(eq(counters.id, 1))
  .returning({ value: counters.value })
  .get();

if (!updated) throw new Error("COUNTER_NOT_FOUND");

sql`` ทำหน้าที่อะไร

sql เป็น tagged template ของ Drizzle สำหรับเขียน SQL expression ที่นำไปประกอบกับ query ได้ ตัวอย่างนี้ให้ฐานข้อมูลคำนวณค่าเพิ่มใน update เดียว แทนการอ่านค่าเดิมมาก่อน 

value: sql`${counters.value} + ${step}`
  • ${counters.value} เป็นการอ้างถึงคอลัมน์จริงในตาราง
  • ${step} เป็นค่าที่ Drizzle bind เป็น parameter ไม่ได้ต่อเป็น SQL string
  • ส่วน + คือ operator SQL ที่อยู่ใน expression

ใช้ sql`` เมื่อ query builder ทั่วไปไม่พอ เช่นคำนวณในคอลัมน์, ฟังก์ชัน SQL หรือ expression เฉพาะฐานข้อมูล อย่านำ input จากผู้ใช้ไปต่อเป็น SQL text เอง และไม่ใช้ sql.raw() กับข้อมูลที่ไม่น่าเชื่อถือ

ตัวอย่างนี้เป็นคำสั่งเดียว จึงไม่มีช่วงอ่านค่าแล้วเขียนทับจากค่าที่ล้าสมัย หากต้องทำหลายการเปลี่ยนแปลงให้สำเร็จพร้อมกัน ให้ครอบด้วย transaction

รายงานยอดขายและสรุปข้อมูล

ใช้ count(), sum(), groupBy() และ having() รวมรายการขายแยกตามสินค้า: 

import { count, gt, sum } from "drizzle-orm";
import { saleItems } from "./db";

const report = db
  .select({
    itemName: saleItems.name,
    itemLines: count(),
    unitsSold: sum(saleItems.quantity),
    revenueSatang: sum(saleItems.lineTotalSatang),
  })
  .from(saleItems)
  .groupBy(saleItems.name)
  .having(gt(sum(saleItems.quantity), 10))
  .all();

groupBy() รวมแถวตามคอลัมน์ที่ระบุ ส่วน having() กรองผลหลังการรวมกลุ่ม ค่า sum() อาจเป็น null เมื่อไม่มีข้อมูล ควรจัดการกรณีนี้ก่อนคำนวณยอดต่อ

รายงานยอดขายรายวันควรคำนวณเวลาเริ่มและสิ้นสุดของวันตาม timezone ที่ API กำหนด แล้วกรองช่วงแบบรวมเวลาเริ่มแต่ไม่รวมเวลาสิ้นสุด ([start, end)) ก่อนนำ count() และ sum(sales.totalSatang) มาคำนวณ

Upsert — จัดการข้อมูลเมื่อชน unique key

ตาราง users มี unique username จึงใช้เป็น conflict target ได้:

import { users } from "./db";

// สร้าง hash ด้วย bcrypt ก่อนเรียก query
db.insert(users)
  .values({
    username: "staff",
    passwordHash: bcryptHash,
    createdAt: new Date().toISOString(),
  })
  .onConflictDoNothing({ target: users.username })
  .run();

ถ้ากฎของงานต้องการแทนค่าที่มีอยู่จริง ๆ ใช้ onConflictDoUpdate():

db.insert(users)
  .values({
    username,
    passwordHash,
    createdAt: new Date().toISOString(),
  })
  .onConflictDoUpdate({
    target: users.username,
    set: { passwordHash },
  })
  .run();
ใช้ onConflictDoUpdate() เฉพาะเมื่อการเขียนทับเป็นกฎธุรกิจที่ตั้งใจ เช่นซิงก์ข้อมูลจากแหล่งที่เชื่อถือได้ ไม่ควรใช้กับสมัครสมาชิกทั่วไปที่ควรแจ้ง username ซ้ำ และ passwordHash ต้องเป็น bcrypt hash ก่อนบันทึก

Migrations — จัดการการเปลี่ยน schema

migration แยกการเปลี่ยนโครงสร้างตารางออกจากการรันแอป ช่วยให้ทีมตรวจสอบ และนำ schema version เดียวกันไปใช้ในแต่ละ environment ได้

ตัวอย่างไฟล์ server/drizzle.config.ts:

import { defineConfig } from "drizzle-kit";

export default defineConfig({
  schema: "./src/db/schema.ts",
  out: "./drizzle",
  dialect: "sqlite",
  dbCredentials: {
    url: "./data/store.sqlite",
  },
});

หลังติดตั้ง drizzle-kit และสร้าง config แล้ว รันจากโฟลเดอร์ server:

npm install --save-dev drizzle-kit
npx drizzle-kit generate
npx drizzle-kit migrate

# ใช้ push เพื่อทดลองใน development เท่านั้น

ขณะเขียนคู่มือนี้ server/package.json ยังไม่มี drizzle-kit และยังไม่มี drizzle.config.ts ดังนั้นคำสั่งข้างต้นเป็นขั้นตอนสำหรับ ตั้งค่าเพิ่ม ไม่ใช่สคริปต์ที่รันได้ทันทีใน repository นี้

Use case: เพิ่มสินค้าแล้วอ่านกลับ

ลำดับการทำงานแบบ service สั้น ๆ:

  1. ตรวจ request body ที่ route หรือ validation layer
  2. เรียก service เพื่อ insert ข้อมูล
  3. ใช้ row ที่ Drizzle คืนมาเป็น response
  4. ถ้าอ่านหรือแก้ไขไม่พบ row ให้ตอบ 404 ตาม API spec
const product = createProduct({
  name: "Milk 1L",
  amount: 24,
  priceSatang: 2500,
});

const loaded = getProductById(product.id);
console.log(loaded?.name); // "Milk 1L"
งานDrizzle patternกรณีร้านค้า
เพิ่มinsert().values()สร้างสินค้าใหม่
อ่านselect().from().where()ค้นหาสินค้าด้วย ID
แก้update().set().where()ปรับชื่อ ราคา หรือจำนวน
ลบdelete().where()ลบสินค้าที่ไม่มีสต็อก/ไม่ต้องใช้

ข้อควรจำ

  • ใช้ eq(), and() และ expression ของ Drizzle ในเงื่อนไข ไม่ต่อ input เป็น SQL string
  • ใช้ NewProduct และ Product จาก schema เพื่อให้ TypeScript ช่วยตรวจ field
  • การมี schema ใน TypeScript ไม่ได้แปลว่าตารางใน SQLite ถูกสร้างแล้ว ต้องใช้ migration/SQL
  • ตรวจว่าคำสั่ง update/delete กระทบ row ที่ต้องการจริง และแปลงกรณีไม่พบเป็น 404
  • ใช้ transaction เมื่อการทำงานหลายคำสั่งต้องคงความถูกต้องของสต็อกและยอดขาย
  • เก็บเงินเป็นจำนวนเต็มหน่วยสตางค์ เช่น 2500 แทนการใช้เลขทศนิยมเป็นบาท

ตัวอย่างนี้อิง TypeScript, Drizzle ORM และ SQLite ผ่าน better-sqlite3
